## 1. 本次目标

建立一套可重复、可恢复并兼容 Windows/Linux 的数据处理流程：

1. 只提取原始 STEMNIST ZIP 中的压力帧数据。
2. 按 `train:val:test = 70:15:15` 进行确定性分层划分。
3. 将全部压力数据转换为保持空间结构的二值脉冲数据。
4. 将完整脉冲数据压缩为单个 ZIP，便于通过 GitHub 在服务器和本地之间传输。
5. 提供安全解压、完整性检查、断点续算和进度显示。

## 2. 已完成内容

### 2.1 压力数据准备

文件：`src/data/prepare_data.ipynb`

- 只读取原始 `.h5` 文件中的压力帧数据。
- 每个样本形状为 `[240, 16, 16]`，数据类型为 `uint8`。
- 使用固定随机种子 `42` 和 `per-class-sha256-sort-v1` 算法分层划分。
- 基于稳定的 SHA-256 排序实现，划分结果不依赖操作系统、设备或文件遍历顺序。
- 输出到 `data/pressure/train|val|test`。
- 每个 split 保存一个 `pressure.npy` 和对应的 `manifest.csv`。
- 保存 `metadata.json` 和总划分清单 `split_manifest.csv`。

### 2.2 完整数据集脉冲编码

文件：`src/data/spike_encoding.ipynb`

- 编码范围从试验集扩展到全部 7700 个样本。
- 输入和输出形状保持一致：`[N, 240, 16, 16]`。
- 输出为仅包含 `0/1` 的 `uint8` 二值脉冲。
- 16×16 个传感点分别进行独立编码，不进行空间聚合。
- 保留参考电路的固定参数和语义：
  - `duration = 2.0 s`
  - `dt = 20 μs`
  - `v_arm = 1.55`
  - `v_fire = 1.25`
  - 不应期 `0.5 ms`
  - 240 个输出时间分箱
- 使用 Numba 在 CPU 上并行编译传感点状态循环。
- 使用 `float64`，禁用 `fastmath`，保证与参考实现的一致性。
- 模拟、下降沿检测和时间分箱在同一内核中完成，不保存 100001 点中间波形。
- 以小批次处理数据并写入内存映射数组，降低内存占用。
- 每批完成后刷新数组并原子更新 `progress.json`。
- 支持断点续算；配置指纹不一致时拒绝错误续算。
- 完成后先验证全部输出，再将临时目录原子替换为 `data/spike`。

## 5. Linux 服务器运行流程

```bash
git clone git@github.com:Four-Q/STEMNIST_Classify.git
cd STEMNIST_Classify
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
jupyter lab
```

由于数据目录被 Git 忽略，需要另外把原始 `STEMNIST Dataset.zip` 上传到服务器的 `data` 目录，然后：

1. 运行 `src/data/prepare_data.ipynb`，生成 `data/pressure`。
2. 运行 `src/data/spike_encoding.ipynb`，完成全量编码和 `data/spike.zip` 压缩。
3. 确认 Notebook 输出的 ZIP 大小和 SHA-256。
4. 只提交 `data/spike.zip`，不要提交解压后的 `.npy` 文件。

```bash
git add data/spike.zip
git commit -m "Add encoded spike dataset archive"
git push
```

本地拉取更新后运行 `src/data/prepare_spike_data.ipynb`，即可恢复 `data/spike`。
